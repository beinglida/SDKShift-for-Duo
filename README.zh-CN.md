# SDKShift for Duo

[English](README.md) | **简体中文**

通过覆写 LaunchServices 中记录的应用 SDK 版本标记，探索 iPhone Duo 的显示兼容性。快捷操作默认目标跟随当前设备的 iOS 版本（27.1 → 27.1.0；27.2.1 → 27.2.1），也可逐应用自定义 SDK 标记。本工具不会重新编译应用、升级 iOS，也不保证实现原生 Duo 布局。

> **应用修改后，请完整重启 iPhone。** 单独注销 SpringBoard 不能保证 SDK 相关服务和应用状态重新加载。数据库写入验证成功不等于界面已生效；本项目尚未验证可靠的免重启刷新方式。

## 功能

- 三页界面：应用、记录、关于。变更审阅、预检和写入已合并到应用页；有待处理操作时才显示底部操作栏，展开数量可检查或移除条目。检查报告始终可从应用页工具栏打开。
- 每个应用可设置不同 SDK，包括已达到或高于当前默认版本 的应用；逐应用添加修改或还原操作，在写入前审阅新旧版本。
- 输入 `主版本.次版本` 或 `主版本.次版本.修订版`，主版本范围 1–99，其余 0–99；两段版本自动补零。编辑器阻止无效输入及相同值提交，并提示降级。这些是格式范围，不代表对应 SDK 已发布或兼容。
- 不写入预检：检查候选数据库，报告写权限和文件锁结果。预检仍创建应用内临时文件并访问缓存，不是完全无副作用的离线检查。
- 原始 SDK 与上次写入值分开保存，支持早期 SDKShift 恢复记录迁移。
- 写入前复查 SDK 快照、串行访问引擎，最多保存 30 条本地操作记录。
- 使用设备内名称生成字母头像，不联网查询图标。
- **默认英文，支持简体中文、繁体中文、日语、韩语、西班牙语、法语、德语、越南语，共九种语言。** 在 首页顶部的 **应用语言** 中切换，选择会保存并立即生效，不影响 SDK 设置或恢复记录。新增七种语言覆盖界面与操作提示，底层引擎错误暂时回退英文；简体中文另有引擎错误翻译。技术日志及已有报告快照保留原文，便于排查。

## 构建与签名

1. 用 Xcode 打开 `SDKShift.xcodeproj`。已使用 Xcode 27.2 编译，最低部署版本为 iOS 27.0。
2. 在 Signing & Capabilities 选择自己的 Team。本地工程当前包含所有者的 Team 配置，其他开发者需替换。
3. 注册该团队可使用的 Bundle ID 与 App Group。
4. 保持 `SDKShift.entitlements`、`Sources/FDEngine.m` 中的 `FDAppGroup` 和签名描述文件一致。当前组名 `group.com.sheldonfornet.sdkshift` 不是通用授权。
5. 若重新生成工程，同步修改 `project.yml` 中的签名配置。
6. 连接并信任 iPhone，启用开发者模式，构建运行。

工程已加入 AI 生成的原创深青色图标，以折叠双屏和双向箭头表达 SDK 兼容标记切换，没有沿用 ForceDuo 图标。

## 使用流程

1. 在“应用”页面扫描，默认显示所有应用；可打开筛选仅显示低于当前默认版本 的条目。
2. 点击应用卡片的“自定义 SDK”，输入如 `27.3.1`，点击“加入变更”。再次打开编辑器可修改待处理目标；“使用 [版本号]”可填入系统对应的默认值，卡片上的快捷“加入变更”也会将较旧版本设为该值。在“应用”页底部展开“待处理”，检查每个应用的新旧版本。更高的标记不会添加 API，也不代表对应 SDK 已兼容。
3. 执行“1. 预检，不写入”。检查完整报告，尤其是写权限和文件锁结果，不要仅依赖完成标题。
4. 执行“2. 写入变更”并确认，然后**完整重启手机**。
5. 检查目标应用的内外屏、横竖屏和操作表现。
6. 需要还原时，在符合条件的应用卡片点击“还原”，审阅并写入还原队列，然后再次重启。

重新扫描会清空待处理队列，避免继续应用旧快照。应用更新或数据库重建可能移除覆写。SDKShift 使用独立数据容器，不自动导入其他工具保存的原值；请先在原工具中还原之前的修改，再交由 SDKShift 管理。

应用页顶部显示**已修改 SDK**分组，下方为**其他应用**，同一应用不重复显示。已修改分组依据 SDKShift 保存的恢复记录：当前 SDK 必须与记录的写入值一致，且不同于原值；卡片显示原值 → 当前值。搜索同时作用于两个分组，“低于当前默认版本”筛选只作用于其他应用。仅加入队列尚未写入的应用不会被视为已修改；还原后会移出该分组。其他工具修改且没有本项目记录的应用无法可靠识别。

两个应用分组均可展开、折叠并记住状态。排序菜单支持名称正序、倒序、名称文字类型及 SDK 从高到低，并保存选择。文字类型仅描述应用名称，不代表应用界面语言；纯汉字名称无法可靠区分中文和日文。页面右侧固定显示 A–Z / # 竖向索引，不随内容滚动。点按或上下拖动可跳到当前排序中首个匹配应用，拖动时显示放大字母；没有对应应用的字母变灰，滑过时跳到最近的非空字母。索引采用 44 点宽的 UIKit 触摸区；卡片使用提前布局的自适应网格，保证屏幕外的跳转目标也参与布局，代价是首次布局工作量比懒加载更大。点击“已修改 SDK”或“其他应用”标题会选中并展开该组，高亮标题对应右侧索引。独立箭头用于折叠；当前组折叠或筛选为空时隐藏索引，不自动跳到另一组。索引归属会被记住，索引顶部图标仅作为当前组提示。索引旁预留空间，不遮挡卡片或底部变更操作栏。名称转写为拉丁首字母（汉字使用拼音），数字和符号归入 `#`。搜索与筛选会同步更新索引。

## 架构

| 文件 | 职责 |
| --- | --- |
| `Sources/ShiftInterface.swift` | 卡片应用库及内嵌变更操作栏、操作记录、设置与语言选择 |
| `Sources/ShiftWorkspace.swift` | 变更请求、恢复点、持久化与旧数据迁移 |
| `Sources/CacheGateway.swift` | 串行引擎适配、版本复查、运行时本地化 |
| `Sources/FDEngine.m/.h` | 注明来源的数据库访问、解析和验证写入引擎 |
| `Sources/worse_query.m/.h` | 第三方沙盒扩展实现 |
| `Sources/*.lproj` | 九种界面语言与本地化消息 |

应用层已重写；数据库引擎和 worse_query 仍是注明来源的依赖，不宣称全部独立原创。

## 为什么不将注销作为生效流程

引擎写入 `.csstore` 并回读验证，但没有实现经过验证的系统级缓存失效协议。SpringBoard、LaunchServices 和应用进程可能保留不同状态；桌面重新加载不等于所有使用方都刷新。

这不证明注销在任何情况下都无效，也不证明单独重启 `lsd` 就足够。完整重启仍是本项目支持的使用流程。worse_query 提供特定目录访问能力，不提供通用系统服务管理权限。

## 验证与限制

此前实现曾在 iPhone Duo / iOS 27.2 上读取到 604 字节 Bundle 记录，解析出 400 个应用。早期 SDKShift 已完成签名、安装和启动。重写界面和双语版本通过本地编译，但不代表所有目标应用效果或所有屏幕尺寸都已完成视觉验证。

回归检查覆盖恢复记录迁移、还原、SDK 漂移、目标版本过滤、忙碌状态保护和持久化。启动时不会自动写入 SDK。卸载前请保存恢复数据。

在 macOS 上运行以下检查，不访问手机或写入真实系统缓存：

```sh

/tmp/sdkshift-workspace-checks

```

### 索引定位验证

索引改为测量卡片在滚动内容中的位置，直接设置所属 UIScrollView 的滚动偏移，替代此前没有生效的嵌套 ScrollViewReader 跳转。260 个模拟应用的测试确认 M → Z → A 的实际偏移为 26465.67 → 54805.67 → 305.67 点。修改前已记录到触摸事件及跳转回调。修复后的完整拖动验证因 Device Hub 窗口控制超时尚未完成，以上坐标测试不代表真机验证。

默认值在本机读取 `ProcessInfo.operatingSystemVersion`，包含修订版本号，不查询网上最新 SDK，也不取编译工具的 SDK 版本。iOS 更新后，下次启动本应用时采用新系统版本；不会自动改写之前设置过的应用 SDK 或恢复记录。
